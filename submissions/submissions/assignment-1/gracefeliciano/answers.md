ANSWER_1: The error occured when the Course Material Portal tries to read the portal.conf configuration file but Linux denies it permission to access the file or do the read action.
ANSWER_2: The file is owned by root and belongs to the course-portal group. When the given permission is converted into octal notation, they become 600. The notation 600 means that owner can read and write on the file, while the group and the others have no permissions regarding the file. Since the course-portal user is only a member of the file's group but is not the owner, it cannot read the configuration file. Thus, Linux denied it to read the file.
ANSWER_3: 640
ANSWER_3_WHY: Only 640 is the smallest fix and suitable option. The reason why the other three are wrong is because they either fail to resolve the issue or give unnecessary permission. 400 only lessens the permission of the owner to read only permission, 755 gives an unnecessary execute permission to owner, unnecessary execute permission to the group which should only be allowed to read, and too much permissions for others which should have no permission while, 777 is risky since it basically gives all permissions (read, write, and execute) or in this case, an unnecessary execute permission to the owner, unnecessary write and execute permission to the group which again, should only be able to read, and giving all permissions to others which shouldn't be able to access the file for security. I followed the least-privilege concept.
